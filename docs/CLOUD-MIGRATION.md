# BrickLab 3D — перенос на облачный сервер

Ветка: `feature/cloud-migration`. Базовая версия редактора сохраняется; GitHub Pages и `feature/mechanics-core` не изменяются.

## Этап 1 — HTTP и контейнер

Сервер Node.js 22 использует встроенный HTTP-модуль, не требует новых runtime-зависимостей. Он раздаёт редактор, каталог, модели, примеры и локальные библиотеки с одного origin. Разрешены только публичные каталоги и index.html; конфигурации, серверный код, скрытые файлы и обход каталогов запрещены. Gzip-пакеты передаются как исходные байты (без Content-Encoding), поскольку браузерный движок распаковывает их самостоятельно.

### Локальный запуск

```sh
npm start
curl -fsS http://localhost:8080/api/health
npm run test:server
```

Откройте http://localhost:8080/. Для запуска только на локальном интерфейсе: `HOST=127.0.0.1 npm start`. Сервер принимает HOST и PORT через переменные окружения.

### Docker Compose

```sh
cp .env.example .env
docker compose up -d --build
docker compose ps
curl -fsS http://127.0.0.1:8080/api/health
docker compose logs -f bricklab
```

Контейнер работает от непривилегированного пользователя, с read-only файловой системой, healthcheck и graceful shutdown. По умолчанию порт опубликован только на loopback хоста. Для публичного доступа подключите reverse proxy с HTTPS к 127.0.0.1:8080; для управляемого контейнерного хостинга используйте Dockerfile и PORT провайдера. Не открывайте публичный HTTP-порт вместо TLS. Секреты не размещайте в src, assets, catalog или других публичных каталогах и не коммитьте .env.

### Важно для переезда

- Сборки пока остаются в localStorage браузера. Другой домен/порт — другой origin: старые проекты не появятся автоматически. Перед переездом экспортируйте важные сборки в .bricklab. Позже нужен импорт и проверяемая миграция в облако.
- Текущий HTTP API содержит только GET/HEAD /api/health. Авторизация, база данных и запись на сервер пока не реализованы.
- Внешние PDF и CDN пока работают как раньше. Сам сервер не устраняет CORS и не предоставляет произвольный прокси.
- Существующие тесты запускаются через npm test; HTTP smoke-тесты включены в общий набор. Docker-образ следует собрать и проверить на целевом хосте.

## Следующие этапы

1. PostgreSQL и миграции схемы (пользователи, проекты, ревизии, владелец, видимость). Отдельный сервис БД и постоянный том; не публиковать порт БД.
2. Аутентификация, сессии, серверная проверка прав и CSRF-защита; только затем API сохранения моделей.
3. Перенос localStorage и .bricklab с подтверждением пользователем, без удаления исходных сборок до проверки.
4. Серверный Rebrickable API с ключом в окружении, лимитами запросов и кешем; ключ никогда не попадает в клиентский JS.
5. Получение и обработка разрешённых PDF: ограниченный список источников, SSRF-защита, контроль размера, фоновые задания и кеш распознавания.
6. Галерея, публикации и модерация; затем совместные комнаты с версионированными операциями.
7. Резервные копии, HTTPS, мониторинг и нагрузочные проверки.
