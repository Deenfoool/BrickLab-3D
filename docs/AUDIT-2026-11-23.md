## Известные ограничения и оставшиеся риски

### P1 — важно исправить до массового ОБТ

1. **Инструкции: CORS и распознавание деталей.**
   - `src/sets/instructions.js` использует встроенный `iframe` для недоступного по CORS удалённого LEGO PDF. Сам PDF при таком показе может быть виден, но байты файла не попадают в движок распознавания. Для неиндексированных страниц артикулы не появятся автоматически.
   - Сайты могут запретить встраивание PDF через `X-Frame-Options`/`Content-Security-Policy`. Поэтому fallback «загрузить PDF с компьютера» необходим, а для безусловной автоматизации нужен разрешённый серверный прокси/источник.
   - `src/sets/instruction-recognition.js` зависит от стороннего OCR CDN. Проверить на PDF с несколькими слоями и эталонной ведомостью деталей (например, известной страницей 123).
   - **Статус:** техническое ограничение подтверждено архитектурой, процент успешного распознавания в этом аудите не замерялся.

2. **Каталог наборов требует собственный API-ключ Rebrickable от каждого пользователя.**
   - `src/sets/rebrickable.js` отказывает без `apiKey`, `src/sets/catalog.js` предлагает пользователю вводить ключ; по умолчанию локально доступен стартовый набор. Это расходится с целью «любой посетитель видит все доступные наборы».
   - Ключ хранится только в памяти страницы и теряется при обновлении (UI об этом предупреждает). Не надо публиковать общий секрет в браузерном JavaScript. Для большого каталога нужен backend с лимитами/кешированием и соблюдением условий API.
   - **Статус:** архитектурный/продуктовый разрыв, не исправлено.

3. **Хранение сборок только в одном ключе LocalStorage.**
   - `src/projects/documents.js`: `bricklab.projects.v1` содержит всю коллекцию. Ограниченный объём LocalStorage означает риск отказа сохранения больших проектов и ограничение числа сборок. Экспорт в `.bricklab` есть, но IndexedDB со схемой миграции нужен для масштабирования.
   - **Статус:** риск отказа сохранения при квоте, не воспроизведён в браузере; не исправлено.

4. **Недостаточно интеграционных тестов на реальные большие сборки.**
   - Тесты механики и `scene-snap` существуют, но без проверок полного сценария импорта → геометрии → snap/групп → сохранения → повторного открытия `8845`, `858`, `42215` трудно оценить качество перед ОБТ.
   - **Статус:** пробел тестового покрытия; реальные дефекты на этих моделях данным аудитом не воспроизводились.

### P2 — исправить при стабилизации

5. **Локально загруженные инструкции не переживают перезагрузку страницы.**
   - `src/sets/instructions.js` сохраняет пользовательские `File` в модульный `Map`, но не в IndexedDB или File System Access API. При перезагрузке повторная загрузка PDF потребуется.
   - **Статус:** подтверждено кодом; не исправлено.

6. **Генерация превью может быть дорогой для больших коллекций.**
   - `src/menu/home-previews.js` запускает WebGL-рендеринг моделей при показе карточек. Есть ленивое наблюдение и кеш, но при массовой обработке тяжёлых моделей нужны измерения памяти и времени генерации; проверить на слабых GPU, при полном кеше и при отключённом WebGL.
   - **Статус:** потенциальная проблема производительности, в браузере не подтверждена.

7. **Недостаточная валидация импортируемого `.bricklab`.**
   - `src/projects/documents.js` проверяет базовую структуру документа, но не размеры коллекций, типы и конечность координат всех деталей и корректность концов соединений. Редактор позже отсеивает часть несовместимых сущностей, однако некорректный импорт может закончиться ошибкой загрузки.
   - **Статус:** риск подтверждён структурой валидатора; необходим отдельный безопасный импорт с сохранением совместимости старых документов.
