# SEO / поиск BrickLab 3D

## Перед развёртыванием

- GitHub Actions не используются. Выполнить штатные тесты на VPS (в том числе tests/seo.test.js и tests/seo-discovery.test.js).
- Dockerfile рендерит три JPG из существующего изображения коробки передач BrickLab: /assets/seo/og.jpg (1200×630), /assets/seo/social-square.jpg (1080×1080), /assets/seo/presentation.jpg (1920×1080). Исходник — scripts/render-seo-banners.sh; локальный запуск требует ImageMagick и DejaVu Sans. Без сгенерированного OG используется существующее изображение.
- После релиза проверить HTTP 200 и Content-Type для /robots.txt, /sitemap.xml, /editor, /instructions, /sets, /sets/42215-1, /parts, /parts/2780, /updates, /learn, /en, /assets/seo/og.jpg. Для неизвестных деталей/наборов ожидается 404. Проверить баннер визуально.
- В карте сайта наборы берутся из локального индекса подтверждённых источников и известных книг; данные карточек обогащаются доступными локальными описями. Детали — из реестра библиотеки. В первой итерации индексируется до 500 именованных деталей с категориями; остальные доступны по прямому URL, но помечены noindex до обогащения. Никаких запросов к стороннему каталогу на каждый обход роботом.
- Публичные пользовательские сборки выключены для SEO по умолчанию. После проверки условий публичного размещения и уведомления пользователей установите BRICKLAB_SEO_PUBLIC_BUILDS=true при включённом сообществе. В карту включаются до 200 свежих работ с содержательным описанием; карточка проверяет существование публичной работы и видимого профиля на каждый запрос. Снятые публикации не выдаются из кеша. Приватные проекты, документы, геометрия, контакты не запрашиваются.
- Администрирование → SEO показывает результаты HTTP-проверок, количество URL и наличие метатегов, а не реальные показы и клики поисковика.

## Вебмастер и Search Console

В кабинете владельца добавьте https://bricklab-3d.ru/ в https://webmaster.yandex.ru/ и https://search.google.com/search-console. Выберите подтверждение HTML-метатегом (для Google — ресурс с префиксом URL, либо DNS TXT для доменного ресурса).

На VPS в существующий .env добавьте только полученные значения, не выдумывая их:
```dotenv
BRICKLAB_YANDEX_VERIFICATION=
BRICKLAB_GOOGLE_VERIFICATION=
BRICKLAB_METRIKA_ID=
BRICKLAB_METRIKA_ENABLED=false
BRICKLAB_SEO_PUBLIC_BUILDS=false
```
Compose передаёт значения серверу. После утверждённого пересоздания контейнера проверьте наличие метатегов в исходном HTML главной страницы, нажмите подтверждение в сервисах. Отправьте https://bricklab-3d.ru/sitemap.xml и основные страницы на переобход. DNS или учётные записи в сервисах этим релизом не изменяются; выдача не гарантируется.

## Яндекс Метрика

Создайте счётчик на https://metrika.yandex.ru/, отключите Вебвизор, добавьте цель JavaScript-события open_editor. Полученный ID запишите в BRICKLAB_METRIKA_ID. До включения согласуйте политику конфиденциальности и режим согласия, проверьте действующую CSP Nginx по официальной документации https://yandex.ru/support/metrica/ru/code/install-counter-csp, не ослабляйте CSP целиком. Затем включите BRICKLAB_METRIKA_ENABLED=true и проверьте согласие/отказ/отзыв, CSP и поступление тестового визита/цели. По умолчанию загрузка выключена, даже при заданном ID. Счётчик работает только на информационных страницах после явного согласия; приватные маршруты SPA, оплата и страницы пользовательских сборок исключены. Это не аналитика всего приложения. Для статистики регистрации, покупки и работы в редакторе потребуется отдельная приватностная проверка и безопасное внедрение событий.

## После запуска

Внешние проверки: статус URL, число проиндексированных страниц, запросы, показы, CTR в Вебмастере и Search Console. Не путать успешный ответ sitemap и метатег с подтверждённой индексацией. В SEO-разделе админки есть ссылки на кабинеты; интеграция внешней статистики через OAuth не включена.

При расширении каталога обновляйте исходные справочники и добавляйте содержательные карточки и статьи, а не массовые дубли. Англоязычная страница /en — первая версия; полный перевод всех карточек ещё не сделан.
