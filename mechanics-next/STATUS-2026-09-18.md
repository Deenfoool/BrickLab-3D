## Implemented architecture

### Native connectivity and part intelligence

- Independent Mechanics Next LDCad parser and Shadow resolver.
- Native LDraw inheritance layer.
- Native connectivity provider using the pinned LDCad Shadow Library snapshot.
- Built-in BrickLab connectors normalized into the same endpoint model as LDraw parts.
- Stable native endpoint identities plus temporary V4-compatible aliases for migration.
- Lazy Part Intelligence registry and immutable catalog observation.
- Mechanical fingerprints.
- Explicit evidence/confidence hierarchy.
- Endpoint semantics for studs, Technic pins, axles, round holes, clips, hinges, ball/socket, turntables, linear guides and other supported families.
- Built-in slider / slider-rail connectors normalized as linear guides.

### Structural constraints

- Full 6-DOF relative-motion representation.
- Revolute, prismatic, cylindrical, spherical, fixed and custom relations.
- Multi-contact bundle solver.
- Rigidity is derived from the full contact bundle instead of being inferred from part names.
- Two separated pin/stud contacts can become rigid while coaxial contacts retain rotation.
- Post-connection world-frame validation.
- Axis polarity is preserved between opposite connector frames.

### Snapping and occupancy

- Native profile matcher.
- Multi-section cylinder profiles.
- Axial fit solver.
- Native occupancy ledger with exclusive female receivers and interval occupancy for long axle/pin/bar elements.
- Candidate scoring and placement solver.
- Transactional native commit with rollback.
- BUILD ownership handoff is gated; V4 remains temporary fallback only before the native project becomes authoritative.
- Native detach/remove operations.
- Native project graph is the authoritative graph after handoff.

### Transmission system

Implemented native transmission models include:

- external spur gear mesh;
- bevel gear mesh;
- shaft/keyed rotation coupling;
- structural LEGO differential;
- packaged/open differential with explicit input/left/right ports;
- rack-and-pinion;
- packaged F/N/R gearbox;
- packaged worm drive;
- universal joint;
- CV joint;
- linear actuator screw relation;
- driving-ring / clutch relations;
- nonlinear displacement propagation.

Important implementation details:

- Differential is solved by equations rather than carrier-child animation.
- Packaged gearbox/differential ports are modeled as revolute bearings plus transmission equations. They are not welded to the housing.
- Shaft coupling honors world-axis polarity.
- F/N/R mode changes are represented explicitly; Neutral removes kinematic transmission and the physics coupling is being migrated to live fixed-step switching.
- Rack geometry is published by the current rack part implementation and consumed by native rack/pinion discovery.
- Transmission-family coverage is included in the migration gate so an unsupported family cannot silently take production ownership.
- Pulley/sprocket remain fail-closed until an explicit belt/chain relation exists.

### Compound mechanisms

Implemented:

- shortcut decomposition;
- stable child-member identity using path + occurrence;
- scene member proxies;
- real child LDraw bounds;
- endpoint ownership inside compound shortcuts;
- universal joint and CV joint semantics;
- actuator and shock/spring topology;
- compound state registry;
- compound project persistence.

For SIMULATE:

- physics-only compound graph expansion replaces opaque roots with physical child bodies;
- external constraints are remapped to the exact child member that owns the endpoint;
- ambiguous endpoint ownership blocks simulation instead of guessing;
- explicit fixed joints can be emitted across compound-member boundaries;
- child Rapier bodies keep their corresponding Three.js scene proxies;
- materialization and rollback are transactional.

### Physics core

Implemented Mechanics Next physics layers:

- structural joint planning;
- Rapier adapter;
- fixed/revolute/prismatic/cylindrical/spherical support where representable;
- generalized transmission couplings;
- motor torque runtime;
- joint resistance/friction layer;
- dynamic release/revalidation infrastructure;
- compound child-body materialization;
- spring/damper materialization;
- transaction-safe cleanup;
- explicit BrickLab scene-unit convention (studs, not hidden metre conversion);

### BUILD / KINEMATICS / SIMULATE migration

BUILD:

- deterministic migration preparation barrier;
- native project handoff after gate;
- native snap preview;
- native transactional commit;
- native detach;
- native UI/project connection records;
- stale V4 background reconcile and inspector overlay disabled after native BUILD takeover;
- New/Open/Undo/project replacement revoke ownership and re-run migration preparation;
- asynchronous LDraw/Shadow readiness retries BUILD handoff.

KINEMATICS:

- gated Mechanics Next owner;
- selected gear/shaft/wheel can be driven through the generic DOF solver;
- drag-to-rotate path is independent of the old shaft solver;
- old KINEMATICS fallback is forbidden once the project is native-authoritative.

SIMULATE:

- gated Mechanics Next owner;
- Mechanics Next creates an isolated production session or fails before legacy fallback;
- once BUILD is native-authoritative, stale legacy physics fallback is forbidden;
- compound roots can be removed from the base Rapier scene and replaced by native child bodies;
- Mechanics Next fixed-step hook runs inside the authoritative physics microstep;
- ownership ledger records the physics-constraint handoff only after successful native install.

## Persistence and migration safety

- Native project schema stores stable instance/endpoint identity, structural connections, special relations and compound state.
- Derived transmissions are recomputed rather than serialized as truth.
- Save/Open stores `mechanicsNext` state.
- Restore is fail-closed and transactional.
- Persisted connections are reinterpreted using the current mechanical semantics before they enter the graph.
- Old packaged gearbox axle-lock records migrate to revolute transmission-port bearings on restore.
- Special relations are also reinterpreted.
- Compound state is applied only after full compatibility proof.
- Axial occupancy intervals survive project round-trip.
- Invalid or partially incompatible restores roll back already-created constraints.
- Restored links become interpreter-owned native records and remain revalidatable.

## Migration gate

The production migration gate currently checks:

- runtime presence;
- Part Intelligence coverage;
- zero unresolved live connections;
- stable compound decomposition;
- differential diagnostics;
- physics preflight;
- native/V4 parity for LDraw parts;
- native-only validity for built-in parts;
- project persistence compatibility;
- deterministic migration regression suite;
- transmission-family coverage;
- unambiguous packaged transmission port bindings.

A project is not allowed to gain production ownership merely because the runtime loaded.

## Remaining release work

The remaining work to release Mechanics Next as the only production mechanics engine is:

1. Finish live SIMULATE controls.
   - Motor RPM/direction must be read live by the native motor runtime.
   - F/N/R physics coupling must switch Forward / Neutral / Reverse inside fixed steps without restarting Rapier.

2. Eliminate physics dual-write.
   - A Mechanics Next production session must be marked before legacy runtime extensions initialize their mechanical joints/forces.
   - Legacy motor, gear, rack, steering/suspension and articulated-driveline writers must not create competing mechanics inside a native-owned session.
   - Visual-only legacy helpers may remain temporarily if they do not own physics.

3. Finish transmission-family release audit.
   - Confirm the built-in F/N/R gearbox, packaged differential, packaged worm drive and rack/pinion in real scenes.
   - Pulley/sprocket remain intentionally blocked until explicit belt/chain topology exists.

4. Finish KINEMATICS regression scenarios.
   - Differential driven from every valid port.
   - Gear/shaft/wheel drag direction.
   - Under-determined differential behavior.
   - Rack/pinion and packaged transmission behavior.
   - Universal/CV joint angle cases.

5. Finish full persistence/history regression.
   - Save → Open → Undo/Redo → move/rotate → revalidate.
   - Legacy project import.
   - Native-only project import.
   - Compound state and occupancy round-trip.

6. Run the complete repository test suite and browser regression suite in a real checkout.
   - `npm run test:mechanics-next`
   - physics/architecture/import-map/project tests;

   - real model smoke tests.

7. Complete Stage 11 ownership handoff.
   - BUILD, KINEMATICS and SIMULATE all native-authoritative.
   - No stale fallback after takeover.
   - Ownership ledger reports every mechanics domain as Mechanics Next.

8. Stage 12 legacy purge and release.
   - Remove V4/legacy mechanics ownership paths and compatibility bridges that are no longer needed.
   - Remove old kinematics/physics hacks.
   - Final architecture/import cleanup.
   - Final `gh-pages` release verification and merge/publish only after the regression gate is green.

## Release definition

The release is complete only when an existing project and a newly built project can both run:

`BUILD → KINEMATICS → SIMULATE → BUILD`

without two mechanics engines competing, without lost connections, without stale persisted topology, and without part-ID solver hacks.

Current coarse release estimate: approximately 70–75% complete.

Current fixed roadmap counter: 2 of 12 stages remain.
