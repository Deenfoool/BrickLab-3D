# Experimental editor
Keep feature/editor-lab separate from feature/cloud-migration. Stage the tested SHA with scripts/prepare-editor-lab.sh; no production checkout, DB or Docker changes. The example nginx locations belong only to the existing preview HTTPS vhost. Verify its actual configuration before applying. Serve using standard nginx MIME types (especially JavaScript, JSON, CSS). Never proxy the preview API to production. The editor uses separate localStorage slots for model and world; importing replaces the current slot after confirmation. Download .bricklab backups.
World v1: explicit stud-grid rectangle and row tool using existing LDraw 3024 and 3005 models. One undo operation per fill; nominal plate-level stacking and coarse AABB overlap checks against existing geometry (not exact stud fit). Generated parts are editable, and the world document is marked static for future simulation; no physical map loading, no brush/terrain generation, no vehicle test drive in world mode. Performance and correct stacking need browser validation. Do not merge this branch into production until experimental behavior is accepted.

## Environment
World defaults to Day; mechanical mode to Studio. Select Day/Sunset/Night/Studio independently per mode. Stage downloads three CC0 Grab3D panoramas as local files and validates PNG headers, dimensions and size before switching the symlink. No hotlinks from browser. World decor uses instanced blocks and studs, not physical LEGO parts; never enters picking or assembly. Texture failures retain previous scene and loaded textures are disposed on switches and editor shutdown. Verify WebGL and background framing in browser.

## World gesture tools
World mode has 20 LDU grid and mouse-driven brush, rectangular area, axis-aligned wall. Left drag paints a preview using a bounded instanced mesh, release commits one undoable operation. Right/middle camera controls remain, Escape exits tool. The current level is an explicit construction plane, rows repeat in 8/24 LDU increments. The brush fills sampled gaps with integer line interpolation, deduplicates visited cells, and limits strokes to 256 parts and worlds to 3000 for bulk operations. Preview shapes are approximate, not exact part meshes. Normal library placement remains available in Ordinary assembly. No vehicle physics integration yet.

## Smart masonry
Smart layout defaults on. It greedily packs real rectangular catalog plates, bricks or tiles into the exact stud region; each design is filtered against the loaded catalog, and actual transformed LDraw width/depth is checked before any scene commit. It uses 90-degree orientation when needed, alternate starter strips for brick courses, and an opt-out for manual 1x1 layout. Tile rows are limited to one because tiles have no top studs. Brush remains one-stud width. The planner guarantees exact cell coverage for valid regions, not a globally minimal part count or structural verification. Preview reports resulting part count and stud-layer coverage. Limits apply to generated part count plus 8192 stud-layers per operation. Browser geometry and performance checks still pending.

## Road builder
Four mouse gesture presets: axis-aligned straight, square 90-degree corner, centered cross, T intersection (horizontal through road, branch follows drag Z). Width 9/13/17/21/25 studs, sidewalks 0–3 studs each side, optional plate foundation, dashed/solid/none center markings, configurable surface colors. One operation builds an exact nonoverlapping mask of rectangular plate and tile pieces via smart layout; crossings have no center markings at the junction. Preview displays part colors. End-to-end joining of independently placed straight roads requires aligned endpoints; no automatic merging/replacement of existing roads, no curved geometry or traffic simulation. Geometry validation and part limits remain in the editor. No tests or deployment performed for this iteration.

## Rounded roads, joining and terrain
Rounded 90-degree turns rasterize a quarter-circle annulus on the stud grid, with selectable or automatic radius. Generated road pieces carry original pose/footprint/role metadata; overlapping same-level intact generated roads are repacked atomically, retaining footprints outside the new segment. Asphalt takes priority over sidewalks and perpendicular crossings clear conflicting center markings. Grouped, locked, hidden or connected pieces are protected; manually changed or copied parts remain ordinary geometry and block overlap. Old roads generated before metadata support cannot be automatically merged. Terrain presets generate solid stepped hills, slopes, stairs, basins and deterministic bumps from real plates/bricks. A basin is constructed with low center, not excavation of existing parts. No smooth curved slope parts, exact collision simulation, or terrain editing by subtraction yet. Tests and deployment intentionally not run.

Auto-join is on by default and can be disabled. Endpoints snap within two studs of intact road centerline cross-sections at the same surface height, including unmarked straight roads. Intersecting generated pieces are repacked; auto-join off preserves ordinary collision rejection. Road status reports the number of pieces being replaced. No tests run.

## World module library
Built-in platform, steps, bumps, bridge, wall and hill presets use the same catalog planner. Save up to 256 visible selected parts as a reusable module (32 local records), including internal verified connections and belts. WebGL thumbnail uses the existing preview renderer when available. Search, category filter, rename, delete, import/export .brickmodule; import validates bounded records and catalog geometry. Placement uses actual part ghosts, one-stud grid, explicit construction level, Q/E quarter turns, Escape cancellation and repeat clicks. Each instance has new IDs and a named scene group, is one undo operation, and is checked against existing geometry via conservative bounding boxes. No dynamic obstacle physics; modules are static geometry for now. Tests and deployment not performed.

Built-in presets can be copied into the personal module library, with real thumbnails generated on demand. Imported modules are normalized before storing and receive a thumbnail if possible. Rename also supports category changes; closing the dialog is prevented while an import or preview is being prepared.

## World test drive
World documents are static map snapshots; the model editor can select My BrickLab World as a venue. The loader loads only visible known parts, instances repeated visual designs/colors, merges matching adjacent static collision boxes, strips studs from recognized upright System body bounds, and uses real triangle meshes for bounded slope geometry. Other intricate parts use oriented bounding boxes. A finite 81x81-stud platform is the ground. Rapier physical and existing kinematic driving use the same map; tire impulses use assigned surface friction in physical mode. Spawn position/heading/optional explicit plate level and surface assignments are persisted and undoable. The actual run validates the spawn via raycast. Physics and graphics are disposed when the editor closes. No dynamic obstacles, destruction, or per-brick dynamics. The Rapier loader currently uses its existing CDN dependency. No tests or deployment run.
