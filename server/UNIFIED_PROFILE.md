# Unified profile / portfolio

One shared hero and styling for owner and public visitor. Editing and publication management live in account settings. Private profile data stays private unless the owner explicitly publishes and consents to synchronization. Migration 020 preserves existing public cards and their UUIDs; the legacy snapshot remains unchanged until the owner explicitly saves the unified profile. Re-publishing uses the same public URL, but removing a publication retains the existing behavior of deleting its public builds and discussions (private models remain).

Portfolio configuration is server-stored, with eight reorderable blocks, visibility controls, one featured public build, and up to six custom collections of published builds. The API validates the shape and filters build IDs against the owner's current publications. Hidden collection contents, pinned ID and biography are omitted from the visitor projection. Published works and social metrics may still be available via normal community routes when a portfolio block is hidden. Award showcase includes only confirmed server awards, with an explicit opt-in. Public calendar represents dates of latest revisions of currently published builds; private calendar represents retained cloud revision saves (26-week display, UTC). Statistics are actual public counts, not invented skill ratings. Pinned work uses the existing protected public 3D preview and viewer dialog; no always-running second WebGL scene.

All six premium signatures retain existing entitlement checks and get portfolio-specific styling. No payment changes. Telegram worker and notification queue unchanged. Tests: unified-profile.test.js, cloud-workshop.test.js, fullscreen-workshop.test.js, community-db.test.js, unified_profile.sql. The normal VPS deploy script runs isolated tests before changing production. Browser and real PostgreSQL checks must be performed on the VPS.
